# Ejercicio 2.2 · Construcción para la verificación

## Ficha de operación 1 · Filtrar licitaciones

| Elemento                      | Registro de la operación                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Funcionalidad y operación** | Filtrar licitaciones por palabra clave, región y tipo. Módulo y firma: `src/features/licitaciones/licitacionFilters.js` — `filterLicitaciones(licitaciones, filters)`. Se utiliza desde `LicitacionesExplorerPage.jsx`.                                                                                                                                                                                                                                                                                                                                        |
| **Propósito**                 | Devolver al explorador la lista de licitaciones que coincide con los filtros activos, para que el usuario encuentre convocatorias relevantes.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Precondiciones**            | 1. `licitaciones` es un arreglo de objetos; cada objeto contiene `title`, `region` y `type` como texto. <br>2. `filters` es un objeto. `keyword`, `region` y `tipo` son opcionales y, si se proporcionan, son texto. Un filtro vacío significa que no se aplica ese criterio.                                                                                                                                                                                                                                                                                  |
| **Postcondiciones**           | 1. Devuelve un arreglo nuevo que contiene solo los registros que coinciden simultáneamente con todos los filtros activos, conservando el orden original. <br>2. No modifica el catálogo de entrada; si no hay coincidencias, devuelve un arreglo vacío.                                                                                                                                                                                                                                                                                                        |
| **Invariante**                | Cada registro devuelto cumple todos los criterios activos; la función no altera el catálogo ni los filtros recibidos.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Validación defensiva**      | **Entrada inválida 1:** `licitaciones` es `null` o no es un arreglo. **Respuesta:** rechazar inmediatamente con un error claro que indique que `licitaciones` debe ser un arreglo. <br><br>**Entrada inválida 2:** `filters.keyword` (o `region`/`tipo`) no es texto. **Respuesta:** rechazar con un error claro que identifique el filtro que debe ser texto. Estas entradas deben validarse en tiempo de ejecución, no solo mediante aserciones.                                                                                                             |
| **Dependencia explícita**     | `filterLicitaciones` es una función pura: recibe el catálogo y los filtros como argumentos, sin requerir un servicio externo. Esta operación no cubre por sí sola la dependencia colaboradora que exige la guía para el equipo. Una de las otras operaciones debe inyectar un colaborador real; por ejemplo, la operación de favoritos puede recibir el almacenamiento como parámetro (`readFavoritosStore(storage)`).                                                                                                                                         |
| **Evidencia de ejecución**    | **Caso válido:** catálogo de prueba y filtros que seleccionan una licitación; comprobar el resultado y el orden. <br>**Inválido 1:** catálogo `null`; comprobar el error definido. <br>**Inválido 2:** `keyword` numérica; comprobar el error definido. <br>Archivo de pruebas: `tests/licitacionFilters.test.js`. Comando: `node --test tests/licitacionFilters.test.js`; luego ejecutar `npm run verify`. **Pendiente:** agregar y ejecutar los dos casos inválidos, y registrar la salida real o una captura; esta ficha no afirma que ya se hayan probado. |

### Nota de alineación con los criterios del proyecto

La implementación actual busca la palabra clave en `title`, pero la historia #43 de `docs/CriteriosAceptacion.md` pide buscar en `title` o `institution`. Antes de cerrar el contrato, el equipo debe acordar el alcance y hacer coincidir la ficha, el código y las pruebas con esa decisión.
