## 2. Decisiones clave y sus efectos

| Decisión                                                                                                                                                                                                                    | Motivo                                                                                                                    | Efecto positivo verificado                                                                                                                                                              | Costo / limitación asumida                                                                                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Separar frontend y backend en dos repositorios** ([#113](https://github.com/Wilson-Jara/LicitacionesUV/issues/113))                                                                                                       | Eliminar lecturas cruzadas de archivos, independizar ciclos de CI y aislar dependencias (`pg` fuera del cliente).         | Cada proyecto se instala con `npm ci` y pasa `npm run verify` en una carpeta limpia sin requerir el otro repositorio ([docs/separacion-backend.md](separacion-backend.md)).             | Actualizar un contrato (como `sector`/`etiquetas`) exige PR coordinados en ambos repositorios y el frontend sube a `v2.0.0` porque ahora requiere la API levantada para mostrar el catálogo.                         |
| **Mantener `node:http` y polimorfismo `IRepositorio` (`list`, `findById`)**                                                                                                                                                 | Minimizar dependencias de ejecución (solo `pg`) y permitir desarrollo/pruebas sin PostgreSQL local.                       | Las pruebas HTTP corren en milisegundos con el catálogo en memoria, mientras CI valida exactamente las mismas rutas contra PostgreSQL 16 ([docs/modularizacion.md](modularizacion.md)). | El enrutamiento, CORS y manejo de errores se mantienen en `src/lib/` en vez de delegarse a un framework externo.                                                                                                     |
| **Extraer reglas de negocio y almacenamiento a módulos `.js` puros** (`persistenciaLocal.js`, `estadisticasUtils.js`, `licitacionFilters.js`, `transaction.js`)                                                             | Evitar duplicación estructural y permitir pruebas deterministas en `node --test` sin DOM ni navegador.                    | Reducción del 50 %–75 % en puntos de edición repetidos en las tres intervenciones ([docs/intervenciones.md](intervenciones.md)) y cobertura JS > 98 % en frontend y > 94 % en backend.  | Los componentes `.jsx` se validan mediante build de Vite y regresión E2E/QA manual ([#128](https://github.com/Wilson-Jara/LicitacionesUV/pull/169), [#163](https://github.com/Wilson-Jara/LicitacionesUV/pull/171)). |
| **Aislar `jsPDF` 4.2.1 en un Web Worker dedicado** ([#49](https://github.com/Wilson-Jara/LicitacionesUV/issues/49), [#135](https://github.com/Wilson-Jara/LicitacionesUV/pull/170))                                         | Evitar bloqueos del hilo principal y acotar la superficie de exposición de la librería externa a llamadas puras de texto. | Descarga fluida sin bloquear navegación, conservación de avisos `@license` en el bundle y mitigación comprobada ante entradas maliciosas (`tests/dependenciaJspdf.test.js`).            | En entornos sin soporte de Web Workers la exportación se rechaza de forma explícita con mensaje accesible (CA5).                                                                                                     |
| **Exigir doble revisión con propietario de QA (`CODEOWNERS`) en `develop` y `main`** ([PR #143](https://github.com/Wilson-Jara/LicitacionesUV/pull/143), [PR #144](https://github.com/Wilson-Jara/LicitacionesUV/pull/144)) | Asegurar trazabilidad y verificación independiente antes de cada integración.                                             | Ningún cambio entra a ramas permanentes sin CI en verde más aprobación de `@StelleC` y otro integrante distinto del autor.                                                              | Cuando QA prepara una rama documental o de pruebas, otro integrante debe abrir el PR para habilitar la revisión cruzada.                                                                                             |

## 6. Notas de versión preparadas para GitHub Releases

### Frontend · `v2.0.0` (compatible con `LicitacionesUV-backend v1.0.0`)

- **Fecha prevista:** noviembre de 2026.
- **Por qué `v2.0.0` (cambio mayor respecto a `v1.0.0`):** a diferencia de `v1.0.0` (que leía datos estáticos internos), la aplicación ahora consume el catálogo y el detalle desde la API independiente en `VITE_API_BASE_URL` (por defecto `http://localhost:3000/api`).
- **Principales cambios:** conexión HTTP y manejo de carga/error (`LicitacionesProvider`, `EstadoCatalogo`), panel `/estadisticas` accesible con cálculo unificado (`#134`), persistencia local compartida y exclusión entre pestañas en umbrales (`#124`, `#125`), perfil editable (`#89`), filtros por sector y etiqueta (`#94`), corrección de diseño y verificación de seguridad en exportación PDF con `jsPDF` 4.2.1 (`#126`, `#135`), contraste WCAG 2.2 AAA (`#145`), licencia MIT y `THIRD_PARTY_NOTICES.md` (`#164`).
- **Cómo actualizar desde `v1.0.0`:** levantar `LicitacionesUV-backend v1.0.0`, copiar `.env.example` a `.env` ajustando `VITE_API_BASE_URL` si cambia el puerto, ejecutar `npm ci` y luego `npm run dev` (o servir la carpeta `dist/` incluida en el paquete ZIP).
- **Limitaciones conocidas:** autenticación, perfil, favoritos y umbrales continúan operando en almacenamiento del navegador; el backend público en Render puede tardar ~1 minuto en despertar tras inactividad.

### Backend · `v1.0.0` (compatible con `LicitacionesUV v2.0.0`)

- **Fecha prevista:** noviembre de 2026.
- **Alcance de la primera versión independiente:** API REST sobre `node:http` (`GET /api/health`, `GET /api/licitaciones`, `GET /api/licitaciones/:id`) con contrato de 11 campos, adaptador PostgreSQL 16 (`pg` 8.23.1) y adaptador en memoria con catálogo ficticio propio cuando no se define `DATABASE_URL`, migraciones concurrentes con bloqueo de sesión y `runInTransaction` (`#6`), normalización de filtros idéntica al explorador (`#5`), validación de enteros seguros en montos (`#7`), licencia MIT y `THIRD_PARTY_NOTICES.md` (`#19`).
- **Puesta en marcha:** `npm ci && npm start` para modo en memoria; con PostgreSQL 16 local, configurar `DATABASE_URL` según `.env.example` y `docs/PostgreSQL.md` y ejecutar `npm run db:setup && npm start`.
- **Limitaciones conocidas:** API de solo lectura sobre licitaciones; aún no incluye sesiones de usuario, endpoints de escritura ni sincronización con Mercado Público.
